# 注释

- 只写代码看不出来的东西：为什么这么做、单位、踩过的坑。不写废话、不复述代码
- 不写行尾注释
- 一行说一件事，不用「；」或句号把几件事串在一行，换行写

## 一看就是生成的，不写

- 复述代码的：`// 导入模块`、`// 定义一个函数来…`、`// 调用 xxx`、`// 返回结果`
- 改动记录：`// 新增`、`// 修改：…`、`// 按要求改为…`、`// 原来是…`
- 空话：`// TODO: 可以进一步优化`、`// 这里处理边界情况`、只写「注意」不说注意什么的、带 emoji 的
- 为了显得完整的：每个函数都配一段把名字再说一遍的 JSDoc、文件末尾的总结、代码里的分节标题（`#` 注释的分隔框除外）
- 同类的非注释：调试用的 `console.log` / `fmt.Println`、「示例用法」代码块、只为了包一层的 helper、没有理由的 try/catch 和空判断

## `#` 注释

- 只用分隔框写，不写散的注释。标题一行，需要时再加一两行说明

  ```
  # ============================================================
  # 标题
  # 说明
  # ============================================================
  ```

## TS、JS 注释

- 需要说明时，导出的函数、类、类型、类的公开方法、带单位的字段用 `/** */`，编辑器悬停时能看到。不是每个都要写
- 函数体里用 `//`，写在要说明的那行上面
- 不用分隔框分段，一个文件一组，文件本身就是分段

## SCSS、CSS 注释

- 用 `/* */`，写在要说明的规则或变量上面。多行时每行开头写 ` * `
- 不用分隔框分段
