# 游戏

跟引擎、平台无关的规矩。web 版见 `dev.web-game.md`。

## 逻辑

- 游戏逻辑按固定步长（1/60 秒）更新：移动、碰撞放固定步长的更新里；动画、镜头、插值放每帧的更新里。随时间变化的量都乘 `dt`，不按帧计数。`dt` 可以缩写
- 每帧的 `dt` 限制在 0 到 0.25 秒之间：从后台切回来后不会一口气补跑上百次逻辑，时间戳往回走时也不会算出负数
- 启动、标题、加载、游戏中、暂停、设置都是游戏内部的状态，用状态机切换
- 按键先转成「动作」（移动、跑、攻击……），游戏代码只处理动作，不直接读按键。键位集中在一张表里，画面上的操作说明从这张表生成
- 速度、动画名这类参数放在配置里，不写死在代码中。动画按名字取，不按序号取
- 会让人移动的动作（翻滚、冲刺攻击、击退）用动画自带的位移：把 root 骨骼的水平位移从动画里取出来，动画原地播，位移交给代码按逻辑步移动角色
- 换角色模型时，用游戏里实测脚着地时的滑动量来定走、跑速度，不靠目测

## 数据

- 数据和素材不放平台的代码里，放仓库根目录的 `data/`、`assets/`，几个平台共用
- 一个仓库里有几个游戏（比如 demo 和正式版）时，`data/`、`assets/` 按项目分子目录，跟项目目录同名（`data/<项目>/`、`assets/<项目>/`），彼此不共用。下面写的 `data/`、`assets/` 都指这一层
- 统一用 JSON，结构以 `data/schema/` 的 JSON Schema 为准，每个 JSON 开头写 `$schema`
- 放进 `data/` 的：游戏内容和玩法规则（物品、配方、武器规格、数值、剧情文本）
- 留在代码里的：跟这个平台的画面和操作绑在一起的（动画名、镜头、界面文案、表现上的时长）

## 素材

- 放 `assets/<类别>/`：`models/`、`environments/`、`textures/<名字>/`，2D 的图放 `images/`。文件名用小写加连字符
- 只用 CC0 或明确允许商用的素材，每加一个都在 `assets/CREDITS.md` 记上来源和许可
- 模型用 GLB。颜色贴图标 sRGB，法线、粗糙度这类数据贴图保持线性
- 自己做的素材的源文件（`.blend`、高精度模型、原图）不放进会部署出去的地方，部署的只放导出的发布版

## 许可

- 游戏不开源。仓库根目录放 `LICENSE`，保留所有权利，写明 `CREDITS.md` 里的第三方素材不算在内
