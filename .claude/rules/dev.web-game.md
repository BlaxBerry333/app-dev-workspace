# web 游戏

three.js 加 React 的游戏。通用的游戏规矩见 `dev.game.md`，项目结构见 `dev.web-app-spa.md`。

## 结构

- 画面、角色和游戏逻辑都不经过 React，React 只负责叠在画面上的 UI
- `useEffect` 的清理函数里把 three.js 的对象 `dispose`
- 每帧要用的临时对象在模块顶层建一次，反复用，不在循环里新建
- three.js 以项目锁定的版本为准：参考同版本 GitHub tag 下的 examples 源码，不凭记忆写；不用带下划线的私有 API。导入写 `import * as THREE from 'three'`
- 功能里的 three.js 部分放 `features/<功能>/3d/`，有才建，里面的文件不加 `<功能>.` 前缀
- 引擎部分放 `utils/`，按用途分组（`loop/`、`input/`、`assets/`、`camera/`）
- `package.json` 写 `"license": "UNLICENSED"`

## 网址

- 不用路由，画面切换用 `dev.game.md` 里的状态机
- 网址只用查询参数，当开发和分享用的开关，比如 `?debug`、`?lang=ja`、`?scene=…`、`?quality=…`
  - 启动时读一次，之后不往网址里写东西
  - 只认白名单里的参数和值，其他的忽略
  - 不放存档、进度这类数据

## 数据和素材

- 别名 `@data/`、`@assets/` 指向这个游戏用的 `data/`、`assets/`（按项目分了子目录的，指向这个项目的子目录），谁都可以用；不加别的别名。`vite.config` 的 `server.fs.allow` 放开到仓库根目录，开发服务器才读得到
- import 里自己的那组按 `@/`、`@data/`、`@assets/`、`./`、样式的顺序排
- 数据用 `@data/` 直接导入，不复制进 src
- 数据的 TS 类型从 schema 生成：`build:data-types` 写到 `src/utils/types/data.ts`，用项目的 prettier 排好，进 git。功能里从它取自己要的那块（`ItemsData['items'][string]`），只有要收窄的（物品 id 的联合类型）才自己写
- `test` 还按 schema 检查 `data/`（`scripts/validate-data.ts`，用 ajv），并检查生成的类型有没有过时。提交前的检查只管 web 项目里的文件，不查 `data/`
- 素材用 `import url from '@assets/….glb?url'` 取网址再交给 loader，打包后文件名带 hash
- `dev/playground/` 的试验不跟别的平台共用，数据和素材放在试验自己的 `src/` 里，不用 `@data/`、`@assets/`

## 画面适配

### 要支持的范围

| 项目 | 范围 |
|---|---|
| 窗口比例 | 16:9 到 32:9（带鱼屏）都铺满，不加黑边。日常开发的窗口是 1920×929（约 2.07:1） |
| 最小窗口 | 1024×600，宽高比至少 4:3。更小、更窄时不显示游戏，只显示「窗口太小」的提示，不做小窗口、竖屏、手机的适配 |
| 屏幕大小 | 笔记本到 4K、5K |
| 浏览器 | Chrome 为主，之后实测 Firefox、Safari |

### 3D 画面

- 竖直视野固定（`PerspectiveCamera.fov` 本来就是竖直方向的），窗口越宽，左右看到的越多
- 比 16:9 窄时，按 16:9 时的水平视野反算竖直视野，保证左右不比 16:9 少
- 每帧渲染的像素总数不超过 2560×1440（约 369 万）。屏幕更大时降低绘制分辨率，由 CSS 拉伸到窗口大小。像素比的上限是 2

### UI

- 按 1920×1080 设计
- 尺寸一律用 `rem`。根字号按窗口高度缩放：1080 高时 16px，限制在 12px–32px（`clamp(12px, 100dvh * 16 / 1080, 32px)`）
- HUD 放在画面中间的安全区里：宽度取「窗口宽」和「窗口高 × 21/9」中较小的那个，居中。带鱼屏上安全区两边不放 HUD
- 文字不做成图片，换语言、缩放时才清晰

### 背景图和 2D 美术

- 不拉伸：背景用 `object-fit: cover` / `background-size: cover`；必须完整显示的用 `contain`；不用 `fill`
- 按 32:9 的比例画，重要的内容（标题、人物）放在中间 16:9 的区域里，也就是宽度的中间一半。左右延伸出去的只画风景，带鱼屏能看到更多，16:9 只显示中间
- 能拆层的就拆层（天空、远景、近景、人物），每层分别定铺满方式和对齐位置
- 准备 1080、1440、2160 高三档，用 `image-set()` 或 `srcset` 让浏览器按屏幕挑。格式用 AVIF 或 WebP

### 验证

改了画面或 UI 之后，在这些窗口尺寸下截图看一遍：

| 尺寸 | 代表什么 |
|---|---|
| 1920×929 | 日常开发 |
| 1920×1080 | 16:9 |
| 2560×1080 | 21:9 |
| 5120×1440 | 32:9 带鱼屏 |
| 3840×2160 | 4K |
| 1280×720 | 小窗口 |
| 1024×768 | 4:3，能用的最窄比例 |
| 1024×600 | 最小窗口 |
| 1023×600、1024×599、1024×1024 | 该显示「窗口太小」的提示 |

## 调试和验证

- 开发时显示调参面板和帧率，只在开发时加载，正式打包里没有。游戏状态挂在 `window.<游戏名>` 上，在 console 里能直接读写
- 改了玩法之后在浏览器里验证：往 `window` 派发带 `code` 的 `KeyboardEvent` 模拟按键，读位置、状态、动画权重，再截图看画面
- 浏览器在后台时 requestAnimationFrame 会停。要验证时先停掉真实的循环（`renderer.setAnimationLoop(null)`），再手动推进主循环，时间戳每次加 1000/60；换成 1000/30、1000/144 能检查帧率无关。验证完恢复真实的循环
